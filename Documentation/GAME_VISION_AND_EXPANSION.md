# الرؤية الشاملة للعبة FarmVsMonsters ونظام توسعتها

**الحالة:** وثيقة مراجعة موسعة؛ مقترحاتها الجديدة تظل قيد مراجعة المستخدم ما لم تُسجل منفصلة كقرارات معتمدة.  
**المسار التقني النشط:** Next.js/React/Phaser داخل `web/` وفق تدقيق المرحلة صفر.

## 1. هوية اللعبة
FarmVsMonsters لعبة ذات عالم مزرعة ومعارك تجمع بين بناء وتطوير المزرعة، جمع النباتات والمحتوى، الدفاع والاستراتيجية، الاستكشاف، والتقدم المستمر. الأركان الإبداعية:
- Build: بناء وتطوير عناصر الدفاع والمزرعة.
- Collect: جمع النباتات والمحتوى والعناصر.
- Battle: معارك استراتيجية واضحة وممتعة.
- Explore: اكتشاف عوالم ومراحل وتحديات.
- Grow: تطور اللاعب ومزرعته ومجموعته.

هذه الرؤية إطار توسعة وليست قيدًا على أفكار مستقبلية.

## 2. دورة اللعب الأساسية
استعداد وتجهيز → تخطيط → مواجهة → تفاعل مع أحداث وقدرات → نتيجة ومكافآت → تطوير → استكشاف → إعادة لعب باستراتيجية مختلفة.
ينبغي أن تكون القواعد والأهداف والمكافآت والتشكيلات والصعوبة والأحداث قابلة للتطوير، مع الحفاظ على وضوح التجربة وعدم تحويل كل شيء إلى إعدادات معقدة.

## 3. أنماط لعب مستهدفة
Campaign، Survival، Challenge، Boss Battles، Endless، Daily Challenge، Special Events، Puzzle، Time Trials، Experimental Modes. هذه قائمة استرشادية؛ لا تعني تنفيذ جميع الأنماط. يجب إعادة استخدام أنظمة المحرك المشتركة حيث أمكن، وإضافة Capability عند الحاجة.

## 4. أنواع المحتوى القابلة للتوسع
- النباتات: هجومية، دفاعية، دعم، علاج، إنتاج، تحكم، هجينة، تفاعلية، نادرة، متعددة التطور.
- الوحوش: أساسية، سريعة، مدرعة، بعيدة المدى، داعمة، متعددة المراحل، تغير مسارها، جماعية، زعماء.
- المقذوفات والأسلحة: مسارات متنوعة، استهداف، اختراق، ارتداد، تتبع، انفجار، تأثيرات.
- البيئة: أرضيات، مناطق مؤثرة، عوائق، عناصر تفاعلية وقابلة للتدمير، ظروف وأحداث.
هذه أمثلة لا قائمة مغلقة.

## 5. إطار القدرات والتأثيرات
يحتاج المحرك إلى إطار قابل للتوسعة لأنواع تأثيرات مثل Damage, Healing, Slow, Freeze, Knockback, Pull, Stun, Shield, Area, Chain, Split, Transform, Spawn, Trap, Steal, Terrain Modification, Buff, Debuff, Control وغيرها.
لا تعرض Studio إعدادًا لميزة غير مدعومة فعليًا. إذا كانت القدرة غير موجودة: تحديد المتطلبات والتبعيات، مراجعة إعادة الاستخدام، تطوير المحرك، إضافة واجهة إدارة، اختبار Sandbox، ثم اعتمادها. بعض القدرات تتطلب تطويرًا برمجيًا وليس مجرد بيانات.

## 6. التفاعلات
نظام موحد يحدد العلاقات بين نبات/وحش/مقذوف/قدرة/بيئة/خريطة/موجة/لاعب. يجب تحديد قواعد التفاعل، الأولوية، التوقيت، التعارضات، الحالات غير المسموح بها، التسجيل التشخيصي، والاختبار. لا تُكرر قواعد متضاربة في كل كيان.

## 7. Gameplay AI
إطار يدعم اكتشاف الأهداف، تقييمها، اتخاذ القرار، الحركة والمسارات، التفاعل مع البيئة، الهجوم، القدرات، الحالات، والاستجابة للتأثيرات. إعداد السلوكيات المدعومة من Studio؛ السلوك الجديد قد يتطلب توسيع المحرك.

## 8. اللاعب والتقدم والحفظ
فصل بيانات اللعبة العامة، محتوى اللعبة، إعدادات اللاعب، تقدم اللاعب، مخزونه، الموارد، المهام، الإنجازات، وسجلات العمليات. تصميم حفظ موثوق، منع تكرار العمليات والمكافآت، التحقق من البيانات الحساسة، التعامل مع انقطاع الاتصال والفشل وإعادة المحاولة، migrations والتوافق والاسترجاع.

## 9. الاستعداد للعب الجماعي
Multiplayer/PvP/التعاون/التبادل ليست ضمن التنفيذ الحالي. لكن فصل بيانات اللاعب، المعرفات الثابتة، API واضحة، والتحقق من العمليات الحساسة يجب أن يمنع التصميم من الاعتماد على العميل أو البيانات المحلية فقط. لا نبني تعقيد multiplayer قبل الحاجة.

## 10. المنصات
مسار التطوير الحالي Browser/Chrome مع Phaser. تحسين responsive واللمس والشاشات والأداء والتوافق تدريجيًا. Android بعد استقرار تجربة المتصفح، ثم دراسة iOS. لا ينقل المشروع إلى Unity/Godot ولا يعاد بناء المحرك دون قرار.

## 11. الجودة
فحص المحتوى والبيانات والعلاقات والأصول والAnimation والترجمة والمسارات والمراحل والتوافق والأداء. حالات Quality: Ready، Warnings، Blocked، Not Tested؛ كل حالة مرتبطة بأدلة وأسباب لا بدرجة مضللة.

## 12. تجربة Studio
Studio يبسط التعقيد الهندسي: بحث مركزي، مكتبة موحدة، واجهة عناصر متناسقة، معاينة، إظهار التفاصيل تدريجيًا، نسخ، تعديل جماعي آمن، مسودات، حفظ، رسائل أخطاء قابلة للإصلاح، دعم العربية. العمليات اليومية لا تتطلب Terminal أو تعديل ملفات.

## 13. AI-Assisted Workflow
مساعد محادثة داخل Studio هو هدف تصميمي، مع إمكانية بدء مسار التعاون من ChatGPT/GitHub دون افتراض API مدفوع. سير العمل: وصف الطلب → تحليل السياق والتبعيات → خطة تغيير → مسودة → اختبارات فعلية → تقرير يوضح المنفذ وغير المنفذ → مراجعة واعتماد. لا حذف أو نشر إنتاجي تلقائي؛ لا ادعاء اختبار غير منفذ. يجب تصميم مسار آمن للوصول إلى المستودع، وليس الادعاء بأن ChatGPT متصل مباشرة بالStudio دون تكامل.

## 14. الاقتصاد والانتشار
اقتصاد قابل للمحاكاة والتحقق، متجر وعروض ومحتوى تجميلي ومشتريات اختيارية مستقبلًا. لا Pay-to-Win غير متوازن ولا معاملات أو مكافآت غير شفافة. المشاركة، تحديات الأصدقاء، Leaderboards، مشاركة الإنجازات، الدعوات، والأحداث الجماعية فرص مستقبلية وليست إلزامًا أو إزعاجًا للاعب.

## 15. التشغيل والحوادث
مراقبة الأخطاء والأداء والتحديثات، تعطيل المحتوى المسبب للمشكلة، rollback، حفظ الأدلة، تحديد العناصر المتأثرة، وتوثيق incident. نشر حزم متماسكة مع recovery لا سلسلة عمليات غير ذرية.

## 16. نطاق المستقبل
Multiplayer، PvP، تداول، Battle Pass، مجتمع واسع، مدفوعات، iOS، API AI مدفوعة هي احتمالات مستقبلية وليست التزامًا حاليًا. القدرات، Localization، Accessibility، وتحسين mobile هي احتياجات بنيوية وتنفذ تدريجيًا.

## 17. شروط توسعة اللعبة
- لا أنواع مغلقة تمنع الإبداع.
- لا إعدادات وهمية.
- لا إعادة كتابة شاملة للمحرك دون حاجة مثبتة.
- لا يوسع المحرك إلا مع تصميم واختبارات وتوثيق.
- كل ميزة قابلة للتوسع عبر مسار موثق، ومراجعة التبعيات والتوافق.
