# Farm Vs Monsters

مشروع لعبة مستقلة مبني على **Unity 3D + C# + URP**، برسومات ثلاثية الأبعاد بأسلوب كرتوني Stylized 3D وكاميرا Isometric. تجمع اللعبة بين معارك دفاع استراتيجية ومزرعة دائمة قابلة للبناء والتطوير.

## حالة المشروع

- تم تثبيت نسخة Unity: **6.3 LTS — 6000.3.27f2**.
- تم إنشاء أنظمة C# الأساسية للمعركة، النباتات، الوحوش، الموجات، الاقتصاد، المزرعة، المحاصيل، الحيوانات، التصنيع، السوق، التخزين والعقود.
- يوجد مولّد داخل Unity Editor لإنشاء مشهد معركة أولي قابل للتجربة مع مجسمات 3D بدائية مؤقتة.
- **لم يتم بعد تشغيل Unity أو تنفيذ أول Build/Playtest**. المجسمات البدائية ليست الرسومات النهائية، وما زال يلزم استبدالها بنماذج شخصيات ونباتات نهائية مع Rig وAnimations وVFX.

## المنصات والأولوية

1. Windows PC — أول نسخة قابلة للعب.
2. Android — بعد تثبيت حلقة اللعب والتحكم.
3. iOS — بعد استقرار نسخة Windows وAndroid.

## إنشاء مشهد المعركة الأول

1. ثبّت Unity Editor بالإصدار المحدد في `ProjectSettings/ProjectVersion.txt`.
2. افتح المشروع من Unity Hub وانتظر اكتمال Package Manager والاستيراد.
3. من القائمة اختر **Farm Vs Monsters → Generate Farm Hub Scene** ثم **Generate Prototype Battle Scene**.
4. شغّل **Farm Vs Monsters → Validate Prototype Battle Scene** لمراجعة المراجع والربط البنيوي.
5. افتح `Assets/Scenes/FarmHub.unity` واضغط Play، وتحرك بالمزارع باستخدام `WASD` أو الأسهم.
6. اضغط **ENTER BATTLE** لبدء المعركة، وبعد انتهائها استخدم **RETURN TO FARM** للعودة إلى المزرعة.
7. في المعركة: `WASD` أو الأسهم للحركة، الأرقام `1–5` لاختيار النبات، وزر الفأرة الأيسر لزراعته على الشبكة. تحرّك فوق كرات الطاقة لجمعها.
8. اضبط **Active Input Handling = Both** في Player Settings إذا لم يكن مضبوطاً.

راجع:
- `Documentation/UNITY_PROJECT_BOOTSTRAP.md` لتثبيت وفتح المشروع.
- `Documentation/FARM_ECONOMY_AND_STORAGE_SETUP.md` لربط أنظمة المزرعة.
- `Documentation/BUILD_LOG.md` لتاريخ التنفيذ والقيود المعروفة.

## حلقة اللعب المستهدفة

اختيار مرحلة ← حركة المزارع ← جمع الطاقة ← اختيار وزراعة النباتات ← مواجهة موجات الوحوش ← فوز/خسارة ← مكافآت ← العودة للمزرعة ← زراعة وإنتاج وتصنيع وتخزين وبيع وتطوير.

## ملاحظة التحقق

وجود الشيفرة والملفات في GitHub لا يعني أن اللعبة بُنيت أو اختُبرت. يجب تشغيل مولّد المشهد داخل Unity، مراجعة Console، إصلاح أخطاء التجميع إن ظهرت، ثم التحقق من الحركة والزراعة والموجات والفوز والخسارة قبل اعتبار النموذج الأولي قابلاً للعب.
